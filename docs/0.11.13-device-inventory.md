# NanoKVM Manager 0.11.13 — configured devices missing from the list

## Fixed

The Manager previously registered its WebSocket backend only after the first
successful device refresh. If every saved device failed setup, the backend was
missing. In addition, `/api/bootstrap` discarded an already fetched device list
when Operations or Update Center returned an unknown-command/not-found error,
and reported a successful empty inventory instead.

The backend now registers at integration setup, independently of device polling,
with an asynchronous lock preventing duplicate concurrent registration. Manager
bootstrap keeps the device inventory separate from optional module failures.
When the NanoKVM backend is unavailable (including a still-running older Core
integration), Manager reads saved NanoKVM entries via HA Core's
`config_entries/get` command. This fallback forwards only public identity and
state fields, never credentials, entry data or options, and does not claim live
availability. An actual inventory-read failure remains an error.

The UI keeps warnings visible, shows saved-but-unloaded devices, disables power
controls without a loaded backend, and explains a genuinely empty device list.
No firmware update or device reset is performed by this change. Legacy NanoKVM
login, token handling and optional endpoint compatibility remain unchanged.

## Installation

After this version has been merged and its add-on image published, update and
start/restart NanoKVM Manager. Then restart **Home Assistant Core**, not only the
add-on, to load the updated integration. Refresh the Manager browser view.
Existing saved NanoKVM entries must not be removed and re-created as part of this
update. If an entry is shown but is not loaded, inspect NanoKVM REST under
Settings → Devices & services and Home Assistant logs for its setup error.

## Verification

Run the isolated production-function and UI regression tests:

```sh
python -m unittest discover -s tests -p 'test_manager_inventory.py' -v
node --check nanokvm_rest/webui/static/app.js
node --test tests/test_manager_ui.cjs
```

The 18 Python tests and 6 Node.js tests passed locally. Python tests execute the
production function bodies with mocked HA transports/framework objects. Node.js
tests execute the actual Manager script with a minimal DOM/HTTP harness. These
are regression tests, not a live Home Assistant or physical NanoKVM test. The
existing repository contract checks and the new tests also run in CI.
